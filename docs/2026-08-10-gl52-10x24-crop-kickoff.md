## 0. What changed between filing this row and writing this kickoff

It was filed as an uninvestigated defect needing a root-cause session. **Then
the five minutes of evidence got taken instead of scheduled, and the shape
changed.** This document is shorter than the row implies it should be, and that
is the finding.

## 1. The measurement — our side is provably not the cause

| Artefact | Dimensions | Aspect |
|---|---|---|
| `db/base_artwork/49.png` (master) | 6656 × 9728 | 0.6842 |
| `db/base_artwork/49_10x24_crop.png` (**the file submitted to Gelato**) | 4053 × 9728 | 0.4166 |
| Target (10/24) | — | 0.4167 |
| Placed rect measured live (`gelato_template_check.py`) | — | 0.4176 |

**The submitted crop preserves every row of pixels in the master.** Height is
identical: 9728 → 9728. That is not a coincidence, it is what the code must do:
`image_crop.cover_crop` on a 0.6842 source against a 0.4167 target takes the
`current_ratio > target_ratio` branch, which computes a new *width* and crops
horizontally only.

**Visual confirmation:** the submitted crop shows the complete thistle head
(ladybird included), the full stem, and generous empty margin at both top and
bottom. Nothing is near an edge.

**Conclusion: the pipeline is arithmetically incapable of removing vertical
content on this path.** The loss the owner saw in the Design editor happened
after we handed the file over.

## 2. The hypothesis, and why it should feel familiar

The 10x24 **portrait template variant's saved placeholder fit/zoom** is
re-cropping a file that arrived correct.

This is GL-48's verdict repeating almost word for word: *the crop maths, the
archived file and the upload were all already correct; the defect came entirely
from the Gelato template, and the owner's dashboard fix was the real fix.* The
portrait template's placeholders were hand-edited on 2026-08-09 to fix exactly
that class of problem — **a hand edit is not a tested change, and this is the
first live product created since.**

Two riders that make the hypothesis more likely, both already on the board:

- **GL-18** records that the *landscape* template still carries the same
  one-placeholder defect, untouched.
- **GL-22a Q2** established that Gelato returns `200` for changes it silently
  drops — this integration has a documented history of accepting an edit and
  not applying it.

## 2b. The owner applied a fix before §3 was run (2026-08-10, evening)

Template re-edited so the placeholders carry images **already cropped to each
variant's aspect ratio**. The mechanism is sound and it is §2's hypothesis
acted on directly: if the saved transform is derived from the authoring image,
authoring at 0.4167 leaves the transform nothing to re-crop.

**§3 below is now partly superseded and partly more urgent.** What changes:

- **§3 steps 1–2 (inspect the saved fit) are moot** — the thing they were going
  to diagnose has been overwritten. The diagnosis is now permanently unavailable
  for this template, which is an acceptable trade for a fix that costs ten
  minutes, but it should be recorded rather than forgotten: **if the defect
  recurs, there is no before-state left to compare against.**
- **A new, higher-probability risk replaces it.** `static_config.json` stores
  `image_placeholder_name`, and this template's placeholder names *are* the
  image filenames. **Swapping the images very likely renamed the
  placeholders**, which is precisely the stale-config defect GL-48 lost eight
  days to, from precisely the same cause: a dashboard edit nothing re-read.
- **The verification burden is unchanged and unmet.** A hand edit is a
  hypothesis. GL-22a Q2 proved Gelato returns `200` for changes it silently
  drops, and a Gelato product **snapshots its placement at create time** — so
  product `3e7abdce-…` is *not* retroactively fixed and cannot be used as
  evidence either way.

### Outcome — the predicted breakage was real (2026-08-10, late)

`python scripts/gelato_template_check.py`, templates-only:

```
MISMATCH 5x7_portrait:   '011_mt_sunday_brook.JPG'              not in live ['55_5x7_crop.png']
MISMATCH 10x24_portrait: '004_doorframe_bottles_madeira_color.JPG' not in live ['65_10x24_crop.png']
(ten other keys ok)
```

Exactly the two variants edited, and nothing else. **`static_config.json`
updated to the live names** — a 2-line diff.

Three things this settles beyond the repair:

1. **All twelve `template_variant_id`s survived.** The check MISMATCHes on a
   missing variant id *before* it reaches the placeholder name, and none did —
   so the dashboard edit swapped images without renumbering variants. That is
   the difference between a two-line fix and re-resolving the whole table.
2. **The new authoring images are on-ratio, measured not assumed.**
   `55_5x7_crop.png` = 6656 × 9318 = **0.7143**, exactly 5/7.
   `65_10x24_crop.png` = 4053 × 9728 = **0.4166** against 10/24 = 0.4167. They
   are pipeline-produced crops, so the transform now has nothing left to
   re-crop. The fix is not merely plausible — its inputs are verified.
3. **The check has now caught the same defect class twice**, and the second
   catch cost two minutes against GL-48's eight days. **Standing rule, worth
   promoting to CLAUDE.md: a Gelato dashboard edit and
   `python scripts/gelato_template_check.py` are one action, not two.**

**Still unverified, and the row stays open on it:** no product has been created
from the repaired template. `3e7abdce-…` snapshots the old placement and cannot
answer this either way.

### Revised first actions, in order

1. **`python scripts/gelato_template_check.py`** — no arguments, read-only,
   templates-only mode. Diffs all twelve config entries against the live
   template and prints `ok` or `MISMATCH` per key. **This exists for exactly
   this moment.** Windows: prefix `PYTHONIOENCODING=utf-8`.
2. If it reports `MISMATCH`, update `static_config.json` from the live values —
   and note that a still-stale entry reaching a real `create-from-template`
   **fails loud by design** (CLAUDE.md's placeholder policy), so the failure
   mode is a blocked create rather than a bad print. That is the good outcome.
3. **Apply the same re-crop to the 5x7 placeholder.** 5x7's submitted crop
   genuinely loses 410px of height (6656 × 9318), so a template over-zoom there
   would *compound* with a real crop rather than merely revealing one. Nobody
   has looked at 5x7 in the editor.
4. **Record that GL-18 / the landscape template is untouched** and still carries
   the original one-placeholder defect. It now differs from portrait in two
   ways, not one.
5. **Verify on the next real create** — `gelato_template_check.py <product_id>`
   *and* an eye on the Design editor. The aspect number alone is blind to this
   defect; that blindness is the entire reason GL-52 exists. Do not tick this
   row on a measurement that could not have failed.

## 3. The check — owner, ~10 minutes (steps 1–2 superseded by §2b)

Product `3e7abdce-c055-4609-ae68-aab19868c5a0` (candidate 49), Gelato Design
editor:

1. Open the **10x24 portrait** variant. Look at the placeholder's **saved
   fit/zoom setting**, not just the rendered result — the question is whether

2. Compare against a variant that renders correctly (8x12 or A2) and note what
   differs. **The difference is the answer.**
3. Take a screenshot of **each** of the six variants while you are in there.
   Cheap now, and the row asked for it.
4. If the 10x24 placeholder is misconfigured: fix it, then **re-verify by
   measurement, not by looking** — `python scripts/gelato_template_check.py
   3e7abdce-c055-4609-ae68-aab19868c5a0` (with `PYTHONIOENCODING=utf-8` on
   Windows), plus a fresh editor screenshot. A `200` and a clean render are not

5. **Check the 5x7 variant while you are there.** Its submitted crop is

**If the 10x24 placeholder turns out to be configured correctly**, the

three sections of a document on a pipeline half that was correct all along.

## 4. The code rider — real, small, and it belongs in E7's session

Whatever the dashboard says, **the pipeline has no instrument that could have
caught this.** `gelato_template_check.py` measures the placed *rectangle*; the
rectangle was correct (0.4176). Nothing anywhere compares the *content* of the
file we submitted to what the template did with it. A human opening the Design
editor is currently the only detector, and it only ran because the owner
happened to look.

Scoped minimally: **have `gelato_template_check.py` print the submitted crop's
own dimensions and aspect beside the measured placed aspect, per variant**, so
"what we sent" and "what was placed" sit on one line. That does not detect a
crop-within-rect on its own, but it turns a two-tool investigation into a
one-command one.

**Fold this into E7 (GL-53) rather than giving it a session.** Both items are
the same sentence — *add the assertion the decision was resting on* — and E7 is
already open in that neighbourhood. E7's kickoff carries it as §3c, marked
droppable if that session runs long.
