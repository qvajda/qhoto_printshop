## 1. Problem

Two defects that look unrelated and are in fact one loop with a missing exit.

**GL-55 — seasonal niches become bad copy with nothing in the way.** Four
candidates in the E9 run (77 `holiday_peak`, 78 `diwali`, 79
`black_friday_cyber_monday`, 81 `new_year_refresh`) reached the owner's
review queue with the event written into the listing description — "for the
holidays", "Black Friday Cyber Monday Sale", "Welcome to the new year" — on
top of artwork that was fine. `compliance_draft.DRAFT_TEXT_PROMPT_TEMPLATE`
interpolates `candidate['niche']` verbatim (`pipeline/compliance_draft.py`,
the `niche: {niche}` clause), and neither `FORBIDDEN_TERMS` /
`FORBIDDEN_WORDS` nor `critic_pass` has any concept of an event or a season.

**Provenance matters and is easy to get wrong.** All five seasonal candidates
(including 80, `engagement_season`, rejected in an earlier session) were
created **2026-08-09T07:00:02Z — before GL-47 shipped** — and sat frozen while
the batch tasks were disabled. Today's re-enable flushed them through for the
first time. **Today's live research cycle produced zero seasonal niches: GL-47
works.** This PRD is not a GL-47 fix and must not be scoped as one. The gap it
addresses is downstream and source-agnostic: a seasonal niche from *any*
origin — a future GL-47 gap, a bug, or backlog like this — becomes a bad draft
unopposed.

**GL-56 — a bad draft on a good design cannot be recovered.** Telegram's
`✏️ Edit` button (`digest.py`, `callback_data` `edit:{group_id}`) reaches
`publish_primary_group.handle_decision`'s `action == "edit"` branch, which
deletes `critic_pass_attempts`, `listing_texts` and `group_messages`, discards
the group contribution, **and then calls
`generate.generate_for_candidate(..., correction_note=decision_notes)`** — a
fresh FLUX generation that can return a visibly different design. There is no
copy-only sibling. Edit is "redo the artwork", full stop.

**The loop:** GL-55 produces good-design/bad-copy candidates, and GL-56 means
the only way to act on one is to destroy the design. E9 alone added four to a
backlog that already existed.

## 2. Success criteria

Testable, in the order a reviewer should check them.

**GL-55**

1. A candidate whose `niche` names a dated event or season does not produce
   listing copy containing that event or season — enforced by an **assertion
   in code that fails loud**, not by prompt instruction alone. Regression test
   asserts the failure, using the four E9 niches as fixtures.
2. The assertion lives next to the decision it enforces and is
   cross-referenced from it, per the standing convention CLAUDE.md records
   from GL-53.
3. Re-running the drafting stage over candidates 77/78/79/81 produces copy an
   owner would publish, or fails loud. Silent partial success is a fail.
4. No regression on the GL-53 guardrail: the forbidden-term and
   digital-download checks still hold, 744+ green.

**GL-56**

5. A new Telegram action, distinct from Edit, redrafts copy only. After it
   runs: `listing_texts` and `critic_pass_attempts` for that candidate are
   fresh; `base_image_*` columns and the artwork files on disk are
   **byte-identical** to before. This is the acceptance test.
6. `✏️ Edit`'s existing behaviour is unchanged — the image redo is wanted and
   is not being replaced.
7. A candidate recovered this way reaches a normal digest entry with normal
   Approve/Edit/Reject buttons; no new terminal state is introduced.
8. The retry/attempt budget is not silently reset or silently exhausted by
   the new path — whichever is chosen, it is stated on the row (open question
   §6.3).

## 3. Scope

**In**

- `pipeline/compliance_draft.py`: seasonal handling in the prompt **and** the
  assertion that enforces it.
- `pipeline/critic_pass.py`: only if the chosen option (§4) requires the
  critic to see season, which the recommended option does not.
- `pipeline/digest.py`: one new inline button + `callback_data` verb.
- `pipeline/publish_primary_group.py`: one new branch in `handle_decision`.
- Tests for both, including the negative cases.
- Board rows and `CLAUDE.md` if a new standing constraint falls out.

**Out**

- **`pipeline/research.py` and GL-47.** Not touched. If the seasonal-source
  question turns out to need research-side work, that is a new row, filed and
  stopped on — not absorbed here.
- Artwork generation of any kind. GL-56 exists precisely to avoid it.
- The GL-10c listing-copy template (post-launch, `docs/2026-08-07-gl10b-listing-copy-spec.md`).
  If GL-55's prompt work overlaps it, note the overlap and leave GL-10c's
  scope alone.
- Bulk recovery of the historical backlog. GL-56 builds the *path*; running it
  over N candidates is an operational step afterwards, and it wants GL-61's
  research-mode toggle first (else the batch piles new candidates on top).

## 4. Options for GL-55 — decide before building

The owner's framing offers a proper fix or a stopgap. Three concrete forms:

**(a) Neutralise at draft time — recommended.** The prompt stops receiving the
raw niche string; it receives a sanitised subject/style descriptor with event
vocabulary stripped, plus an explicit instruction that copy is evergreen. The
assertion then checks the output against a seasonal-term list and raises.
*Why this one:* it is source-agnostic (works on backlog, on a future GL-47
gap, on anything), it is one module, it needs no schema change, and it fails
loud rather than degrading. *Cost:* a seasonal-term list is a maintained list
and will have gaps — mitigated by the assertion being cheap to extend, and by
the list being the same artefact for both halves.

**(b) Filter before drafting.** A seasonal niche never reaches
`compliance_draft`; the candidate is marked and skipped. *Why not, as the
primary:* it strands good artwork — exactly the outcome GL-56 exists to
prevent — and it silently shrinks batch output unless the skip is loud.
Reasonable as a *second* gate behind (a), not instead of it.

**(c) Let the event inform tasteful copy.** The richest option and the one the
owner's "properly" framing points at: a Diwali design *should* be able to say
something about warmth and light without saying "Black Friday Sale". *Why not
now:* it is a copy-quality problem, not a guardrail problem, it has no cheap
assertion (you cannot fail-loud on "tasteful"), and it belongs with GL-10c
post-launch. **Recommendation: build (a) now, record (c) as the eventual
target on GL-55 so the stopgap is not mistaken for the destination.**

Option (a) is what §2's criteria are written against. If the owner picks
differently, the criteria move with it.

## 5. Constraints

- **CLAUDE.md, load-bearing:** the description carries **no** prose AI
  disclosure (`DISCLOSURE_TEXT = ""`), and that is only safe because the
  structured tick happens manually at publish. Nothing in this work
  reintroduces disclosure text, and nothing here touches
  `update_listing_state` (GL-29 stays `# DELIBERATELY UNWIRED`).
- **An instruction in a prompt is a preference, not a control** (CLAUDE.md,
  from GL-53). This is the reason §2.1 and §2.2 are written as assertions.
  A PR that changes only the prompt does not satisfy this PRD.
- **A design is only ever image-generated once.** GL-56 is the option that
  honours this; do not "fix" it by regenerating at lower cost.
- **A swallowed per-item exception must leave a state change behind**
  (CLAUDE.md, from GL-46/GL-54). Applies to the new GL-56 branch: a failed
  copy-only redo writes a reason on the row and still fails the stage once at
  the end.
- Dry-run gates the side effect, never the code path (CLAUDE.md, from GL-48).
  The GL-56 acceptance test in §2.5 must run the same branch it would live.

## 6. Open questions — answer at sign-off

1. **GL-55 option:** (a), (b), (a)+(b), or (c)? Recommendation: (a), with (c)
   recorded as the target.
2. **What counts as seasonal?** Dated retail events (Black Friday, Cyber
   Monday) are unambiguous. Cultural festivals (Diwali) and soft seasons
   ("new year refresh", "engagement season") are less so — and a design's
   *subject* may legitimately be autumnal without its *copy* being seasonal.
   The list needs a stated principle, not just entries.
3. **GL-56 and the retry budget:** does a copy-only redo consume a
   critic-pass attempt against the 3-attempt cap, or reset it? Either is
   defensible; unstated is not.
4. **GL-56 button placement:** a fourth button on every digest entry, or only
   surfaced where it applies? Four buttons on a phone is a real usability cost
   against a real recovery need.
5. **Backlog recovery:** run GL-56 over the existing good-design/bad-copy
   candidates as part of this work, or as a separate operational step after
   GL-61's research-mode toggle exists? Recommendation: separate.

## 7. Plan

**Sequence GL-56 first, GL-55 second.** GL-56 is the smaller, better-specified
build with an unambiguous acceptance test, and it is what makes GL-55's own
fix verifiable on real candidates — with the copy-only path in place, 77/78/79/81
become the live regression set for the seasonal fix instead of four
unrecoverable rows.

1. **Sign-off** on this PRD, including §6.1–§6.5. No code before this.
2. **Session A — GL-56.** New `callback_data` verb + digest button + a
   `handle_decision` branch that runs `compliance_draft` → `critic_pass` and
   touches nothing else. Tests: §2.5 (byte-identical artwork) and §2.6 (Edit
   unchanged). Commit, per the one-stage-one-commit convention.
3. **Session B — GL-55.** The chosen option from §6.1, prompt half and
   assertion half **in one commit** (GL-53's precedent: shipping the prompt
   alone is the failure mode this project has already had once). Fixtures from
   the four E9 niches.
4. **Verification, not a status code.** Re-draft candidates 77/78/79/81
   through the new copy-only path and read the resulting `listing_texts` rows
   in full — the whole row, not the field under test (GL-53's own best
   finding: the digital-download drift class was found only because the audit
   read the whole column).
5. **Board update** on both rows with what actually shipped, and a findings
   doc if either session returns something the rows did not predict.

## 8. What this PRD deliberately does not claim

- That GL-55's list will be complete. It will not be. The claim is that it
  fails loud when it matches and is cheap to extend when it misses.
- That the four E9 candidates are recoverable into *good* listings. They are
  recoverable into *drafted* listings; whether the copy is any good is still
  the owner's eye at digest, and that is by design.
- That this closes the seasonal question. Option (c) — event context producing
  genuinely good seasonal copy — remains open and post-launch.
