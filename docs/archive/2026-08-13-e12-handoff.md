## 2. The three things worth planning around

**(a) The GL-71 verdict came from the incident's own artefacts, not from the
instrument the PRD specified.** The PRD wanted a read between the upload loop and
the reconcile — which can only observe a *future* upload. Etsy's per-image
`created_timestamp` against `telegram_events_log` was strictly better, because it
is from the failure rather than from a re-enactment of it: the upload loop ran in
correct order at correct ranks, four `approve:100` dispatches were accepted, and
**the permutation is confined to exactly the ranks uploaded inside the duplicates'
window** (ranks 1–2 before it and 8–12 after it are clean). Hypothesis B is active
for a whole upload and cannot produce a windowed defect.
**Planning consequence: before scoping an instrument, ask what record the defect
already left.** This is the second time it has paid on this project.

**(b) The fix is shipped but has never fired in production.** The dispatch guard
is proven by three unit tests and by nothing live — no duplicate tap has hit it on
a real listing yet. **The natural instrument already exists and costs nothing:**
77/78/79's re-sent digests are the next real taps, and the owner's parked-GL-65
workaround (tap until it lands) will generate duplicates on its own. A single
`discarded: group already approved` row in `telegram_events_log` is the whole
confirmation. **Do not build a soak for this** — read the log after the next
decisions.

**(c) GL-65 got quietly cheaper.** Its workaround was risky *because* duplicate
taps raced the uploads; that is now guarded. GL-65 itself (client-side callback
loss upstream of Telegram) is unchanged and still parked — but its cost basis
dropped, which is worth knowing if it is ever re-ranked.

## 4. Facts learned this session that cost money to re-learn

- **Etsy refuses to delete a listing's last image** (`"Listings must have at least
  1 image"`). A delete-first gallery repair strands the listing at one stale
  image. Upload first, let the existing reconcile remove the strays — the same
  ordering `patch_etsy_listing`'s own comment already argues for.
- **The Etsy listing editor is not an alt-text instrument.** It renders scaled
  copies and shows its own control labels (`"edit gallery image 2"`), never the
  stored `alt_text`. Owner-eye covers featured image and ordering; the API covers
  alt text. Neither substitutes for the other, in either direction.
- **Etsy now requires `readiness_state_id` on a physical draft create.** Costs us
  nothing (Gelato creates listings) but it is a live trap for any hand-run.
- **`create_draft_listing` was the only Etsy call bypassing `_call_with_refresh`.**
  Fixed. Still unused by any pipeline stage, still correctly so.
