# GL-37 — Etsy Creativity Standards fields: API re-check

Date: 2026-08-06. Read-only research session, no code/DB changes.

## Question

Two Shop Manager fields are blank on every listing this pipeline produces:
1. **"How does your shop produce this item?"** (made from scratch / assembled /
   altered / curated / natural material)
2. **"What tools are used to make this item?"** (handheld / computerized /
   an AI generator / none)

CLAUDE.md has recorded since 2026-07-16 that field 2 (the AI-disclosure
question) has no API field, confirmed via `etsy/open-api#1340`. Re-checked
both fields against the live v3 API and Etsy's current dev-relations
channel.

## What was checked

**1. Live `GET /listings/{id}` — full response dump, not a field lookup.**
Two listings pulled live (after refreshing the expired access token):
- `4549960823` (candidate 42, draft)
- `4542159277` (GL-9 control, draft)

Full response for both listed every field the v3 API returns for a listing:
`listing_id, user_id, shop_id, title, description, rich_description, state,
creation_timestamp, ..., quantity, shop_section_id, url, is_taxable,
is_customizable, is_personalizable, listing_type, tags, materials,
shipping_profile_id, return_policy_id, processing_min/max, who_made,
when_made, is_supply, item_weight/length/width/height, is_private, style,
file_data, has_variations, should_auto_renew, language, price, taxonomy_id,
production_partners, skus, views, readiness_state_id, suggested_title,
shipping_profile, shop, images, videos, user, translations, inventory,
personalization, buyer_price`. Nothing resembling production method, tools,
or "creativity standards" appears anywhere in either response. Confirms the
GET echo doesn't carry it, closing the "read-side name differs from
write-side name" failure mode this project has hit before (GL-34) — there
is no read-side field to alias to begin with.

**2. `GET /seller-taxonomy/nodes/1027/properties`** — all 15 properties
returned for taxonomy_id 1027: `Craft type, Material multi, Primary color,
Secondary color, Width, Height, Depth, Sustainability, Home style, Occasion,
Holiday, Room, Custom1, Custom2, Custom3`. None of these map to production
method or tools-used. This isn't a taxonomy property — rules out the
"maybe it's hiding as a listing property" theory.

**3. `GET /shops/{shop_id}`** (shop 63060058, QhotoArt) — full response
dumped. No production-method or tools field, and nothing that looks like a
settable shop-level default for either question. Question 3 (shop-level
default vs. per-listing) is moot: there's no field to default at either
level via the API.

**4. Dev-relations channel re-check** (`etsy/open-api` GitHub — the repo's
Issues are now disabled; the live channel is GitHub Discussions).
Found **Discussion #1630**, opened 2026-06-22, title: *"Etsy Open API v3 —
Feature Request / Support Ticket - Expose the 'How it's made'
production-process + tools/AI disclosure on createDraftListing /
updateListing."* Full body confirms, in Etsy's own words:

> The listing "How it's made" section includes two fields that are set in
> the Seller Handbook UI but are NOT available in Open API v3 listing
> create/update... Already available via API: `who_made`, `when_made`,
> `is_supply`, `type`, `production_partner_ids`... The only place to set
> [these two] is the listing-editor UI, and the editor's sole save action
> ("Activate with changes") publishes the listing — there is no API path
> and no draft-save.

The requester proposes exactly the field names one would guess
(`production_process` enum, `tools_used` enum array) — proof no such field
exists yet, not evidence one does. As of this check (2026-08-06) the
discussion has one reply ("This would be very helpful"), no Etsy staff
response, no linked PR or changelog entry. Not shipped.

## Answers

1. **Does v3 expose either field today?** No — verified against the full
   raw response of two real listings, not a field-name grep.
2. **Is it a taxonomy property?** No — all 15 properties for taxonomy 1027
   enumerated, none match.
3. **Shop-level default?** No — no such field exists at either level, so
   the "one manual tick ever" question doesn't apply yet.
4. **If settable, which endpoint/field?** N/A — not settable. The one
   endpoint that *can* set it is the Etsy web listing editor, and doing so
   through the UI forces `state: active` (no draft-save path), which
   collides with this project's activation policy
   (`pipeline/etsy_client.update_listing_state` — deliberately unwired,
   activation is a manual per-listing decision, $0.20/listing cost).

## Recommendation

Unchanged from the prior finding: **accept the manual per-listing dashboard
step** as the only way to fill these two fields today, same as listing
activation itself already is. Etsy has an open, unactioned feature request
for exactly this (Discussion #1630) — worth revisiting after that ships,
not before. No code change to file as a follow-up; there is nothing to wire
up. If you want, I can add a link to Discussion #1630 in CLAUDE.md so a
future recheck starts from the tracking issue instead of re-deriving it.
