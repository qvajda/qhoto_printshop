## §1. Why the ordering below is not negotiable

Three constraints chain the steps together, and each one has already cost this
project something when it was violated.

1. **Alt text and rank are set at image-upload time and Etsy v3 has no
   update-image endpoint.** On a draft, repairing either is free — and under the
   standing decision above everything stays a draft, so **this constraint no
   longer creates any time pressure.** It survives here only as the reason the
   *order* is measure → repair: re-uploading a gallery before knowing whether
   `alt_text` is even accepted means doing it twice.
2. **Verify by measurement, not by status code** (`CLAUDE.md`; earned by GL-22a
   Q2, where Gelato returned `200` for a change it silently dropped). A `200` on
   an `alt_text` multipart field is not evidence that Etsy stored it.
3. **Do not ship a fix for an unmeasured cause, and do not ship two changes into
   one observable.** GL-71 has two live hypotheses; a reorder shipped next to a
   dispatch dedupe makes the next permutation uninterpretable. GL-48 is the
   in-house precedent for the related trap: gate the *side effect*, never the
   branch.

## §2. Step 1 — GL-69, the alt-text read-back (live, cheap, reversible)

**Goal:** answer one question with a verbatim record — does Etsy's
`uploadListingImage` accept and persist the `alt_text` multipart field as
`upload_listing_image` now sends it?

**Method**

1. Create a **throwaway draft listing** (not `4554354628`, not any listing with
   a real gallery).
2. Upload **one** image through `etsy_client.upload_listing_image(...,
   alt_text=<a distinctive sentinel string>)`. Use a sentinel that cannot occur
   naturally, so the read-back cannot be satisfied by coincidence.
3. Read the image back with `get_listing_images` and **paste the raw response
   into the findings doc verbatim** — not a summary, not "confirmed". Assert on
   the *value*, matching the GL-57 lesson that Etsy's own returned metadata can
   lag or lie (there, `rank` transiently reported `1` on two images at once).
4. Delete the throwaway draft and the temp image.

**Two outcomes, both already scoped**

| Read-back says | Verdict | Action |
|---|---|---|
| sentinel present | GL-69 closes | proceed to §3; no code change |
| empty / absent / rejected | field name or transport is wrong | fix is **entirely inside `upload_listing_image`** — nothing else depends on it — then re-run this step before proceeding |

**Do not proceed past this step in either outcome without the verbatim record on
disk.** Nothing may re-upload `4554354628`'s gallery until it exists.

### 3a. Confirm the defect still exists (owner change, do this first)

**Before spending a session on causes, confirm the gallery is actually still

GL-71 does not get investigated — it gets re-verified on the next gallery upload
and the row is downgraded, not closed on a single clean read.** Stop here in
that case and go to §4.

### 3b. Discriminate the cause

**The measurement:** in `group_product.patch_etsy_listing`, read the listing's
images **between the upload loop and the reconcile** that deletes Gelato's
seeded previews.

**Discrimination table**

| Observation at that point | Cause | Consequence |
|---|---|---|
| our ranks are already permuted *before* the reconcile | **B** — Etsy inserts-and-shifts around the seeded previews still present | fix = reconcile **before** uploading. The code comment rejecting that ("would leave the listing briefly imageless") is a real concern on a live listing and **not** on a draft nobody can see — so the fix is conditional on listing state, and must say which case it is in rather than guess (same shape as GL-67's scoping rule). |
| our ranks are correct there, permuted only later | **A** — duplicate `approve:100` dispatch raced the uploads | **Owner decision 2026-08-12: fix it in the same session.** The `handle_decision` **dispatch guard** is in scope and does not need re-approval. **GL-74 travels with it** — a single-tap irreversible reject next to a parked-GL-65 workaround whose instruction is *tap until it lands* is the same defect wearing a different hat. Ship the guard; ship the reject confirmation with it. |
| neither cleanly | say so | do not force a verdict onto a third pattern; record it and stop. |

**Only after the verdict is written down** does the fix get written — one change,
one observable, one commit.
