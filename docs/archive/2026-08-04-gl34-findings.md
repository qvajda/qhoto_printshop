# GL-34 findings (2026-08-04)

**Outcome: no defect.** `who_made` stays `i_did`, no code change. The
original GL-13 observation ("production partner missing after patch") was a
response-shape mismatch in whatever check produced it, not an API or
pipeline regression.

## Root cause

The Etsy listing PATCH **request** body sends `production_partner_ids`
(list of ints) — that's the field `patch_etsy_listing` builds from
`listing_texts.production_partner_ids` and the field name CLAUDE.md
documents. The listing **GET response**, however, does not echo that key at
all. It returns a differently-named, differently-shaped field:
`production_partners` (list of `{production_partner_id, partner_name,
location}` objects). A check that read the response for
`production_partner_ids` — the field that exists on the *write* side — would
find nothing, on every listing, regardless of whether the partner is
actually set. That is the "response-echo artifact" the kickoff PRD flagged
as the leading hypothesis, confirmed.

## Observation 1 — the control (GL-9, v4.11 listing 4542159277)

## Conclusion

GL-34 closes as an observation artifact. Whatever produced the original
"partner missing" read on GL-13 was checking `production_partner_ids` (the
write-side field name) against a GET response that only ever returns
`production_partners` (a different key, different shape) — that would read
as "missing" on **every** listing, live or not, defect or not. No pipeline
code touches or needs to touch this; it's a diagnostic-tooling lesson, not a
production bug.
