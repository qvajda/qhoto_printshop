## 2. `primary_mockup` / `group_mockup`: (a) had no natural home either

Unlike `generate`/`compliance_draft`, neither stage had (a) done. Worse: the
`groups` row for the group being rendered is created and **committed** (status
`pending_generation`) *before* `render_group_mockups` runs, so a failure left a
row that read exactly like "hasn't started yet" — the GL-46 failure mode by
name.

`groups.status`'s CHECK constraint has no value for "the render attempt this
row represents just failed" that wouldn't also make the row look terminal
(`failed_abandoned`, `publish_failed`) when it is not — the retry budget for
this stage lives in `create_or_reuse_group_product`, not here, and the row
must still look retryable to the next cycle. `groups.failed_reason` already
exists as a column with no CHECK on it (added for `critic_pass`'s abandon
paths), so both fixes write the exception there on failure, leaving `status`
at `pending_generation`. That satisfies (a) — a diagnosis is durably visible
on the row — without lying about whether a retry can still happen.

## 3. `digest`: option 1 taken, as recommended

No column write. `DigestCycleError` is (b)-only, by design: the kickoff's
reasoning holds up under inspection — `groups.status` has no value meaning "I
could not tell you about this," the group is still legitimately
`pending_review`, and the `group_messages` duplicate-send guard means the next
cycle's retry is a genuine re-send, not a hack. The docstring on
`DigestCycleError` states this explicitly so a future reader doesn't "fix" the
missing (a) as if it were an oversight.

`surface_publish_failed_groups`'s own catch (§3 rider from the kickoff, "the
one that's arguably worse") got the same treatment: a failure there now feeds
the same `DigestCycleError`, so a broken safety net fails loud like everything
else in the stage instead of silently going dark.

## 4. `publish_primary_group.py`: a second, outer swallow

`retry_publish_failed_groups`'s per-candidate loop had (a) already (`publish_candidate`
marks `publish_failed` with a reason before re-raising) but was missing (b).
Fixing that alone wasn't enough: `run_publish_primary_group_cycle` (the actual
stage entrypoint) called `retry_publish_failed_groups` inside its **own**
`try/except: print`, so even a correctly-raising inner function would have
been swallowed a second time, one level up. Both were fixed — the inner
function now raises `PublishFailedRetryError` after finishing every candidate,
and the outer call no longer catches it. The per-Telegram-update loop directly
above it (`publish_primary_group.py:445`) is untouched: it's the GL-45 case
the kickoff named, its own comment block explains why it advances the offset
and logs rather than raising, and sweeping it would have been the regression
the kickoff warned about.

## 5. Tests rewritten because they asserted the swallow

Per the kickoff's warning ("GL-53 found two, watch for it here too") — five
did:

- `test_primary_mockup.py`, `test_group_mockup.py`,
  `test_critic_pass.py`, `test_group_critic_pass.py`,
  `test_digest.py`, `test_group_digest.py`,
  `test_publish_primary_group.py` — each had one `*_isolates_per_*_failures`
  test that asserted the swallow's *symptom* (a shorter processed-list, no
  exception) as if it were the intended behavior. All rewritten to
  `pytest.raises(...CycleError, match=...)`, keeping the original assertion
  that the *other* item in the batch still got processed.
- `test_group_critic_pass.py::test_run_group_critic_pass_cycle_returns_empty_list_when_nothing_ready`
  was worse than a stale assertion — it was accidentally correct for the wrong
  reason. Its setup inserted a gallery with no `listing_texts` row; the
  cycle's select query doesn't filter on `group_products.status`, so the row
  *was* picked up, crashed on the missing `listing_texts`, and the swallow
  turned that crash into the empty list the test asserted, by coincidence.
  Rewritten to use a genuinely unready group (no gallery rendered yet) so the
  test asserts what its name says.
- `test_publish_primary_group.py::test_retry_publish_failed_groups_leaves_group_failed_when_patch_still_fails`
  asserted `retried == []` on a single-candidate failure with no raise at all
  (this function never raised before this session). Rewritten to expect
  `PublishFailedRetryError`.

## 8. The meta-point

Both `primary_mockup` and `group_mockup` were missing (a) with no obvious
column to write it to, and neither was flagged as such by the kickoff (it
only flagged `digest` as "the interesting one"). The pattern generalizes past
the four modules where CLAUDE.md's rule was written down: whenever a stage
creates its own tracking row *before* attempting the risky work rather than
after, "wrote nothing" and "hasn't started" become indistinguishable on
failure, and the fix is either (a) a reason column with no CHECK on it, or a
deliberate, documented decision that (a) doesn't apply here — never silence.
