## 1. The one-paragraph version

Every scene ever generated exists in exactly one place — this desktop —
*except* the bundles git already tracks, which are safe on `origin`. Back up
the difference: the untracked `outputs/gl6_*` batches and the untracked half of
`assets/mockups/inflow/`, each image carried together with its `screen.json` /
sidecar verdict, written once to content- or date-addressed keys under a single
R2 prefix, using the uploader that already exists. Output is the uploaded
corpus plus a committed manifest saying what landed where.

**Do not write a second uploader.** `pipeline/artwork_store._r2_put_object` +
`_sigv4_headers` + `sign_request` are written, tested, and already gated on the
all-or-nothing `config.R2_ENV_VARS` set (`config.is_r2_configured()`).

## 4. Scope

**In:** every file under `outputs/gl6_*` and `assets/mockups/inflow/` that
`git ls-files` does not return, plus the JSON verdict/sidecar files in those
trees regardless of size, plus a manifest.

**Out:** anything git tracks (already on `origin`; the repo is public by
decision — re-uploading is paying twice for the same copy); `db/`; `.env` and
anything matching a secret pattern; `outputs/mockup_qa/` contact sheets unless
they are the only record of a screen; `__pycache__`.

**Explicitly out of this session:** GL-30b, the authoring-time sync. Different
row, post-launch, hooks `scene_intake.py`. Do not start it here — but pick key
names GL-30b can keep using.

**Parked for the owner, not decided by the code:** anything "parked outside the
tree" (the plan mentions `lifestyle_small_kitchenshelf` and material outside
the repo). The script takes an optional extra-roots argument; if there is
nothing outside the tree, that argument stays empty and the session says so.

## 5. Constraints that are not negotiable

1. **Write-once, never overwrite.** A sync that can overwrite is a copy, not a
   backup. Keys are content-addressed (`sha256` of the bytes) or date-prefixed
   under one root, e.g.
   `mockup-corpus/2026-08-08/<relative/path/from/repo/root>` with the sha in the
   manifest — pick one, state it in the manifest header, and make a re-run of
   the script a no-op on already-present keys rather than a re-PUT.
2. **One uploader.** `artwork_store._r2_put_object`. If it needs a small
   refactor to be callable with an arbitrary key from a script, refactor it and
   add a test — do not copy it.
3. **All-or-nothing env gate stays.** If `config.is_r2_configured()` is false,
   fail loud and immediately, before reading a single file. Do not partially
   upload.
4. **Verdict travels with the image.** An image is only "backed up" once its
   `screen.json` / sidecar / `meta.json` is up too. If a directory's images
   upload and its JSON fails, that is a failed run, not a partial success.
5. **Must not delay GL-7 or GL-22.** No shared file, no config change beyond
   additive. If this session finds itself editing `pipeline/`, stop and flag.
6. **Idempotent and resumable.** ~320 MB over a home connection will be
   interrupted at least once. Re-running must skip what already landed
   (HEAD the key or read the manifest) and finish the rest.

## 6. Shape of the work

- `scripts/corpus_backup.py`
  - `--dry-run` (default true): enumerate, size, and print the plan; upload
    nothing.
  - Selection: `git ls-files` diff over the configured roots + optional
    `--extra-root`.
  - Upload via `artwork_store`, sequential, with a per-file log line.
  - Emit `docs/data/2026-08-08-mockup-corpus-manifest.json`: run date, key
    scheme, bucket, and one record per file — relative path, size, sha256, R2
    key, verdict-file key if any, upload status.
- Tests: selection logic (tracked files excluded, mixed dir handled per-file),
  key derivation, the env gate failing closed, and re-run skipping. Mock the
  PUT — no live R2 in unit tests.
- One live run with `--dry-run` reviewed by eye, then the real run.

## 7. Definition of done

1. `--dry-run` output matches the table in §3 within a file or two, and the
   discrepancy is explained rather than shrugged at.
2. Real run completes; every in-scope file has a manifest record with status
   `uploaded`.
3. Manifest committed. **The manifest is the deliverable that survives the
   session** — someone in six months must be able to find any given image from
   it without R2 console archaeology.
4. Re-running the script uploads zero bytes.
5. A spot-check: pick three keys, confirm they exist in R2 and that one of them
   is a `screen.json` whose verdict is readable.
6. `git status` is no dirtier than it was at the start, minus the new script,
   tests and manifest.

## 8. Honest note on the framing

The plan's own scoping note says it: this is insurance on the *untracked*
material, not a data-loss emergency for the corpus as a whole. If the desire is
also "one place to browse everything ever generated", that is a legitimate but
*different* goal, and it means including the tracked bundles too — a stated
choice, not a backup argument. **Default in this session: untracked only.**
Overriding it is an owner decision, made before the script is written, not
after.
